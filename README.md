# Automated Web Application Security Assessment for Financial Platforms

## 1. Project Overview

The **Automated Web Application Security Assessment for Financial Platforms** is a Python-based security scanner designed to assist in the preliminary assessment of web application security.

The scanner performs passive reconnaissance and low-impact security checks to identify web application entry points, including pages, HTML forms, input fields, and potential API endpoints. It generates a structured JSON report containing the collected assessment results.

The project is developed for educational and cybersecurity research purposes, with **OWASP Juice Shop** used as the target application in a controlled testing environment.

## 2. Project Objectives

- Automate the initial reconnaissance of web applications.
- Identify pages, forms, input fields, and potential API endpoints.
- Collect information useful for preliminary security assessments.
- Generate structured JSON reports for analysis and documentation.
- Support learning about web application security and vulnerability assessment.

## 3. Features

- **Automated reconnaissance:** Discovers accessible pages within the target application.
- **Form discovery:** Identifies HTML forms and their associated input fields.
- **Input-point identification:** Records potential locations where user input is accepted.
- **API candidate discovery:** Identifies potential API endpoints for further investigation.
- **JSON reporting:** Saves assessment results in a structured JSON format.
- **Low-impact assessment:** Focuses on passive discovery and limited checks rather than aggressive testing.

## 4. Technologies Used

- **Python** — Main programming language.
- **Requests** — HTTP communication with the target application, if used by the implementation.
- **Beautiful Soup** — HTML parsing, if used by the implementation.

## 6. Requirements

Before running the scanner, ensure that you have:

- Python 3 installed.
- Git installed, if cloning the repository.
- Visual Studio Code or another Python-compatible editor.
- The required Python dependencies.
- A test web application, such as OWASP Juice Shop, running locally or in an authorized lab environment.

## 7. Installation

### Step 1: Clone the repository

```bash
git clone https://github.com/Robert-ux-dev/Financial-Web-Security-Scanner.git
```

### Step 2: Navigate to the project folder

```bash
cd Financial-Web-Security-Scanner
```

### Step 3: Create a virtual environment (recommended)

```bash
python -m venv .venv
```

### Step 4: Activate the virtual environment

On Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
```

### Step 5: Install dependencies

```bash
python -m pip install -r requirements.txt
```

## 8. Running the Scanner

### Step 1: Start the target application

Ensure that OWASP Juice Shop is running and accessible. For example, if it is running locally on port 3000, open:

```text
http://127.0.0.1:3000
```

### Step 2: Run the scanner

From the root directory of the project, execute:

```bash
python src/scanner.py
```

Follow any prompts displayed by the scanner, if applicable. Ensure that the configured target URL points to your authorized test application.

### Step 3: Review the generated report

After the scan completes, inspect the JSON report generated by the scanner. For example:

```text
Reports/report.json
```

The exact output location depends on the configuration in `scanner.py`.

## 9. Sample Report

The JSON report records the information collected during the assessment. Depending on the scanner's implementation, it may include:

- Target application URL.
- Scan start time.
- Pages discovered.
- HTML forms and input points.
- Potential API endpoints.
- Scan mode and other assessment metadata.

The report helps document the reconnaissance process and provides a starting point for further manual security testing.

## 10. Scope and Limitations

The current version focuses on reconnaissance and low-impact checks. It should not be considered a comprehensive vulnerability scanner.

- Discovering an input field does not prove that it is vulnerable.
- Identifying an API candidate does not establish that the endpoint is insecure.
- The scanner may not discover authenticated pages or content rendered entirely by JavaScript.
- Results require manual verification and further testing.
- The scanner does not guarantee detection of every OWASP Top 10 vulnerability.

## 11. Ethical Use

This project is intended for educational purposes and authorized security assessments.

Only scan applications that you own or have explicit permission to test. Use intentionally vulnerable applications such as OWASP Juice Shop for practice, and avoid conducting intrusive tests against live financial platforms without authorization.
